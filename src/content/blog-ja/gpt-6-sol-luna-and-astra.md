2026 年 9 月 22 日、OpenAI は GPT-6 宇宙の拡張を発表した：**GPT-6 Sol** と **GPT-6 Luna**。[1] 公式の論理は明確だ——今月早い時期の **GPT-6 Astra** はなお「最強・最も整列した」ピークモデル；大量の日常仕事はしかし異なる規模・リズム・予算を要する。Sol / Luna は近い訓練方法で、Astra の専門仕事・事実性・符号化・コンピュータ使用・整列上の進展を、より速く安い帯へ敷き、キャッシュと推論で省いたコストを **GPT-5.6 販促価比で API 標価 50% 減** としてユーザーへ返す。[1]

当日やや早く、Anthropic が Claude Opus 5.5 を公開した。両社は密着発版し、読者は価格・能力・安全制限を対照する。姉妹篇は [Claude Opus 5.5：値下げと旗艦性能](/ja/blog/claude-opus-5-5-price-and-performance/)。[2] 本稿は GPT-6 側を独立して書く：Sol / Luna の価位と位置付け、公式が選んだベンチ切片、キャッシュ改善が agent 請求に意味すること、Astra の能力物語（公開検証された Enigma 解読を含む）を副線としてどう読むか、および coding agent をどう分帯するか——「すべてデフォルトで最も高い」ではない。

## 先に三代の役割を分ける：Astra / Sol / Luna

名前を製品階層として覚えるほうが、スローガンを覚えるより有用だ：

| モデル | 公式の役割（OpenAI によれば） | API 識別子 | 本ラウンド標価（百万 token あたり） |
| --- | --- | --- | --- |
| GPT-6 Astra | 全場最良；最も難しく重要なプロジェクトはなおこれ | `gpt-6-astra`（以前公開済み） | 本稿は Sol/Luna 公告で新たな Astra 絶対標価を照合できず、臆造しない |
| GPT-6 Sol | 複雑仕事（符号化含む）の主力コスパ主力帯 | `gpt-6-sol` | 入力 $2、出力 $10（5.6 Sol の $4 / $20 から半減） |
| GPT-6 Luna | 高スループット・目標が明確なタスク（要約・抽出・短い Q&A 等） | `gpt-6-luna` | 入力 $0.10、出力 $0.50（5.6 Luna の $0.20 / $1.20 から引き下げ；出力側公式表は $0.50） |

価格と下げ幅は OpenAI 本品公告の表から。[1] TechCrunch は製品直感を補う：Sol は符号化などの複雑タスク寄り、Luna は文書とバッチの明確目標タスク寄り；Anthropic Opus 5.5 が約 90 分早く公開されたとも指摘する。[3]

可用性（公告当日準拠）：Sol と Luna は ChatGPT Work と Codex に入り、Plus / Pro / Business / Enterprise / Edu 向け；Free と Go はデスクトップで Luna を使える；公告は**当時まだ Chat に入っていない**と明記；API は `gpt-6-sol` / `gpt-6-luna`；安定サービスのため当日段階的に放量。[1]

Astra 主ナラティブは OpenAI 2026-09-03 前後の公開材料と安全概要：公式はコンピュータ使用・閲覧・ソフトウェア工学・ネットワーク安全・科学と専門仕事などでフロンティアにあると主張し、Preparedness 枠下でネットワーク安全能力が Critical 等級に達したモデルとして議論される。[4][5] 本稿は Astra の全ベンチ表を再抄せず、「Sol/Luna が何を下へ渡しているか」の説明に必要なときだけ引用する。

## 価格とキャッシュ：下がるのは百万 token だけではない

### 標価の半減

GPT-5.6 販促価比で、Sol / Luna API は **50% 減**。[1] もともと Sol を符号化デフォルトにしていたチームには直接の予算緩和；Luna を抽出・分類・短返信経路で回すチームには、「安いモデル」をもう一帯押し下げる。

選定時なお問う：**値下げ後、より多くのタスクをより高いモデルへ上げないか？** 枠と心理会計が変わると総支出は上がりうる。分母は「成功完了したタスク / マージ / クローズしたチケット」にし、日消費ドルではない。

### Prompt caching：agent 長対話の第二の刃

OpenAI は GPT-6 の prompt caching 改善を明記する：デフォルトでより高いキャッシュヒット、agent のコンテキスト再利用とより速い応答を助け、**キャッシュヒットした入力 token 読取に 90% 割引**を提供。[1] 付帯能力は：

- Prompt Caching ダッシュボードと診断ツールで未ヒット理由を説明；
- reasoning effort の調整やツールのオンオフ時、既存接頭辞のキャッシュ再利用をできるだけ**中断しない**；
- 明示ブレークポイントで、開発者がキャッシュ接頭辞の終わりを決められる。[1]

GitHub のフィードバック：過去数ヶ月の関連改善で、全新処理が要る prompt token 比率が 50% 超下がった（数十億リクエスト規模）。[1] これは Codex / Copilot 類の長セッションにとって構造変化だ：モデル標価とキャッシュヒット率が掛け合わさる。

### 再現可能な検収手順（内部 runbook へのコピー推奨）

1. キャッシュダッシュボードを開き、同一 agent ワークフローで「同接頭辞・微変接尾辞」リクエストを 50 回走らせ、ヒット率とドルを記録する。
2. 意図的に毎ラウンドでツール JSON のフィールド順や記述措辞を変え、ヒット率の崩壊を観察する——これは harness の問題であり、モデルが値下げしなかったことではない。
3. effort 帯の昇降時に照合：公告はキャッシュを保ったまま effort / ツール可用性を調えられると称する；あなたのラッパー層がシステムプロンプト全体を書き換えるなら、公式最適化は助けない。[1]
4. 「キャッシュ読取割引後の有効入力単価」をレポートに書き、Anthropic 側の「キャッシュ読取標価」と対照するときは、両側の会計科目が同一でないことに注意。

### 「半減」を相殺する三類の請求の罠

1. **帯の上浮**：Sol が安くなったあと、本来 Luna の抽出タスクも Sol に投げ、または Sol 失敗を即座に Astra へ昇格；平均単価が戻る。
2. **キャッシュ未ヒット**：ツール schema・システムプロンプト・ファイル順が毎ラウンドチャーンし、90% キャッシュ読取割引が形骸化する。[1]
3. **再試行ストーム**：事実性が良くなってもゼロ誤りではない；編成層がタイムアウト後に無思考で 5 回再試行すれば、値下げは掛け戻される。

発版週は先にこの三項を直し、その後で「Anthropic の相対コスト図に勝ったか」を語る。

## 公式能力切片：Sol/Luna 自身が選んだ戦場

OpenAI は Sol が全面的に Astra を超えるとは主張しない。ナラティブは：**より低いコストで競品の高価格設定に迫る、または局所で超える**。以下の数字はいずれも Sol/Luna 公告由来のベンダー自己報告で、effort / harness と競品設定は原文脚注と対照が要る。[1]

### 専門ワークフロー

- **AutomationBench**：Sol は xhigh で 33.2%、タスクあたり約 $0.27；Claude Opus 5 max（26.9%）比で約 **9% のタスクあたりコスト**と主張；低 effort の Astra、および Opus 5 フォールバック付き Fable 5.1 設定を超えるとも称する（脚注：Fable コストはフォールバックが完全計上されず過小評価）。[1]
- **Agents' Last Exam**：Sol は max effort で 56.4%、Claude Opus 5 最高点比でタスクあたりコスト約 60% 安いと主張。[1]

これらの数字を読むとき覚える：Anthropic 同日の Opus 5.5 公告では、AutomationBench 上 GPT-6 Astra が 41.4%、Opus 5.5 が 40.0%——**異なる記事・異なるモデル・異なる日付切片を、直接「究極表」に継いではいけない**。[2]

### 事実性

内部事実性評価は、ユーザーが誤りと標した実対話（非識別化済み）に基づく：Sol の誤りはおよそ半減し、Astra 級の信頼性に近くかつより安い；Luna はより高い effort 下で GPT-5.6 Sol 水準を約百分の一コストで達しうる。[1] 公式は同時に宣言する：これらの対話は典型トラフィックを代表しない（典型場面の誤りはより少ない）、かつ点数は長さで厳密制御されていない。[1]

### 符号化

- **FrontierCode 1.1 Main**：Sol は 5.6 Sol 比で明確に上がり、より低いコストで Claude Fable 5.1 xhigh 水準にマッチしうる（公式表述）。[1]
- **DeepSWE v1.1**：Sol max 68.8%、Claude Fable 5 最高 69.9%（xhigh）比で 1.1 ポイント差、タスクあたりコスト約 80% 安い；Luna max 66.6%、Opus 5 / Fable 5 の medium に近い；Opus 5 / Fable 5 比でタスクあたりコスト約 93% / 96% 安い。[1]

OpenAI はさらに内部用量背景を与える：API 価格換算で、研究者の日次 token 用量中央値は $600 超、90 分位は $7000 超——「符号化 agent が長くなったあと、継続コストがタスクを大きくする勇気を決め始める」ことを示すためだ。[1]

### コンピュータ使用

Astra はなおコンピュータ使用上の世界最良と公式が称する；Sol は OSWorld 2.0 offline、xhigh で 60.5%、Claude Opus 5 medium の 60.3% に近く、タスクあたりコスト約 80% 安い；Luna max は GPT-5.6 Sol medium を超えられ、コストは約十分の一。[1]

### 協働文風

Sol/Luna は Astra のコミュニケーション改善を継承する：より明確、jargon が少なく、奇妙な構文が少なく、低価値細部が少なく、やや短いが実質を落とさない。公式はサイト改修「bento + 右上角スライド切替」の例で 5.6 Sol と 6 Sol を対比：後者は早すぎる結論が少なく、自明な細部の反復が少なく、やった／やっていない検査をより率直に述べる。[1]

## 整列と安全：Astra を継承するが「ゲートなし」とみなすな

Sol/Luna は「Astra の整列仕事の上に立つ」；整列評価ではそれぞれの 5.6 対応帯より改善し、符号化仕事での誤導的陳述比率の低下を含む。[1] 評価は意図的に難しい場面を選ぶため典型失敗率を代表しない；細部は system card。[1]

Astra 自体の安全物語はより重い：OpenAI 安全概要はそれを広く配備中で能力最強のモデルの一つと記述し、Preparedness 枠下でネットワーク安全能力を **Critical** に標し、隔離・拒答境界の強化・レッドチームと整列評価などの措置を伴う。[5] **Sol/Luna 公告はこれらの Critical 級制御が各帯へそのまま下ったかを逐項復唱しない**；工学上はデフォルトで：より強いモデル帯の濫用面はより大きく、ルーティングと監査方針はなおタスク機微度で分帯し、「安いモデル = 安全問題なし」や「整列改善 = 監視をオフにできる」と仮定しない。

Anthropic Opus 5.5 との対照（細部は姉妹篇）：Anthropic は生物/ネットワークに透明フォールバックと検証計画を採用；OpenAI 側は Astra で Critical cyber と整列スイートを強調。[2][5] どちらも「裸の旗艦」ではない。coding agent では、「拒答／降格が発火するか」を検収に書くほうが、ニュース稿の安全形容詞を暗記するより有用だ。

## 副線：Astra と MVUEH Enigma——能力物語をどう読むか

 Astra ナラティブを、公開動画の再生数だけで止めてはいけない。照合可能な第三者記録の一つは Crypto Cellar Research：2026-09-15、Carter Leffer がサイト保守者に **GPT-6 Astra** による 1941-07-10 独軍 Enigma 電文 **MVUEH**（2005 年以来未解読）の解読検証を依頼；保守者は鍵と平文が正しいことを確認し、モデルがほとんど人手の暗号解析指導なしに、候補電文を自ら選び、既解読 SIPVX 平文との関連を疑い、シミュレータと Bombe 類ソフトウェアを書き、ROSENOW 反復地名 crib を使って解読を完了したと記述；後続ログにはドイツ連邦公文書館蔵番号への専門検索手がかりさえ現れた。[6]

この副線の読み方：

1. **それが証明するのは長程研究型 agent 能力とツール使用**であり、Sol/Luna の標価や AutomationBench 点ではない。
2. **あなたの製品リポジトリへ直接外挿できない**。暗号解析成功は公開コーパス・コード記述・検索実行可能な環境に依り、「私有 monorepo で規範どおり IF を直す」とは同分布ではない。
3. **「ピークモデルになお単独価値がある」を強化する**：OpenAI 自身も最も難しいプロジェクトはなお Astra を探すと言う；Sol/Luna が解くのは同世代方法を敷くことであり、ピーク帯の取消ではない。[1]
4. YouTube 公式紹介（約二週間で数百万再生規模の信号）は公開ナラティブ入口として適するが、**引用可能な採点出典にしてはいけない**；具体能力は文字公告・system card・照合可能な第三者記録を正とする。[7]

## Opus 5.5 との選び方（本稿独立結論）

| 次元 | GPT-6 Sol / Luna（本稿） | Claude Opus 5.5（要約） |
| --- | --- | --- |
| 役割 | Astra 世代能力を中低価格帯へ敷く | 単一型番で Fable 級能力 + Opus 級価格を狙う |
| 標価 | Sol $2/$10、Luna $0.10/$0.50（5.6 販促価比 -50%） | 入力 $4、出力 $20、キャッシュ読取 $0.20（Opus 5 比典型タスク約 -40%） |

| 安全ナラティブ | Astra 整列を継承；Astra には別途 Critical cyber 物語 | 生物/ネットワーク同級ゲート + 検証計画 + preserved thinking |

**coding agent 分帯提案：**

1. **すでに Codex / ChatGPT Work**：デフォルト符号化帯を 5.6 Sol から 6 Sol へ切替え、同一批リポジトリタスクでマージ率とドルを比べる；バッチ抽出/要約は Luna。
2. **尖峰タスク**（再現しにくいバグ、大型アーキテクチャ移行、失敗代償が高い）：明示的に Astra へルートし、予算キャップを別途設ける。
3. **多ベンダー**：タスク種別でルートし、ブランドではない；両側ニュース稿の「相対コスト」を直接財務モデルに入れない。[1][2]
4. **判断層は分離できる**：構造化意思決定モデルでゲート/ルーティングするなら、チャット旗艦を換えても判断層をやり直す必要はない；当サイト Jev 文。[8]

## なぜ「双モデル下放」と「単旗艦値下げ」は同じ手ではないか

OpenAI と Anthropic の同日動作を「どちらも価格戦争」と言うのは粗い。仕組みが違う：

- **OpenAI**：ピーク（Astra）と規模化（Sol/Luna）を分帯；値下げは中低帯で起こり、ピークはなお「最も難しいプロジェクト」ナラティブを単独販売する。[1]
- **Anthropic**：**一つの** Opus 5.5 で同時に「Fable に近い能力」と「旧 Opus より安い」を狙う；Fable / Mythos はなお防護と検証計画で用途を分け、「安い版旗艦」の単純ではない。[2]

調達とプラットフォーム組にとって、これはルート表のフィールドが違うことを意味する。OpenAI スタックはしばしば「タスク難度 → 三帯モデル」；Claude スタックはしばしば「デフォルト Opus 5.5、機微域はフォールバック発火／検証申請の要否を見る」。両社混用時、相手の帯名が一一対応すると仮定してはいけない。

## 符号化 agent：「大きくする勇気」から「どう大きくするか」へ

OpenAI は内部研究者用量（中央値 >$600/日、90 分位 >$7000/日、API 換算）で一つの転換を示す：agent セッションが時間とリポジトリで計られるようになると、**継続コストがプロダクトマネージャが範囲を大きくする勇気を決め始める**。[1] Sol/Luna の値下げとキャッシュ改善は、この制約に直接作用する。

着地可能な製品方針：

1. **範囲ゲートとモデル帯を結ぶ**。例：単一 PR・単一サービス → Luna または低 effort Sol；リポジトリ横断の IF 契約 → Sol；未知根因の生産事故 → Astra、かつ人手在場を要求。
2. **失敗代償をルートに書く**。事実性評価は Sol が「かつて誤った対話」上で誤り半減を示すが、なおその集合が難寄り・非典型トラフィックだと注意する。[1] 対外顧客に見える返答は事実代償が高く、より高帯または検索照合の追加へ；内部草稿は Luna でよい。
3. **「マージ可能性」を検収にし、「コンパイルできる」ではない**。FrontierCode はマージ可能性（テスト品質、範囲規律、スタイルとリポジトリ規範）を強調する。[1] これは当サイトが harness / 規範ファイル（`AGENTS.md`、スキル等）を論じた方向と一致する：モデルが強くなったあと、規範とゲートの見返りはより高い。
4. **一夜タスクの観察面**。キャッシュヒット、ツール呼び出し回数、拒答有無、範囲の静かな変更——四類指標は単一の「成功/失敗」より請求とリスクを説明しやすい。

### 一週間 A/B シナリオ（Codex / API）

1. 直近の実チケット 12 を選ぶ：機械 4、曖昧多ファイル 4、閲覧または外部文書が要る 4。
2. 対照群：旧デフォルト（例 5.6 Sol）；実験群：6 Sol、effort は生産デフォルトに固定。
3. Luna は別途「要約/フィールド抽出のみ」パイプラインを走らせ、生産コードの直接改修を禁止し、コストと誤り率を観察。
4. Astra は実験群失敗または人手昇格時のみ介入を許し、別会計。
5. 通過線例：ドル ≤ 旧デフォルト 70%（半減後の期待を反映）でマージ級完了率が下がらない；または完了率が上がり人手編集行数が下がる。

半減後もドルがほとんど下がらなければ、先に調べる：静かに Astra へ上がっていないか、Fast/高 effort 全開か、キャッシュヒット崩壊か、再試行倍増か。

本サイト読者の多くは Claude Code を使うが、同じ人々が Codex と双ベンダールートも評価している。推奨読書順：

2. 姉妹篇：Opus 5.5 価位と防護；[2]

## コミュニケーションスタイルもなぜ「コスト」か

公式は意図的に Sol 文風が短く明確になったことを示す。[1] これは agent チームにとって審美の問題ではない：

- PR 記述とセッションログがより短く結論前置なら、**人手監査の人時**が下がる；
- 「できそうに聞こえるが検査していない」措辞が減れば、偽りの自信を下げやすい；
- 多 agent 転送では、短く照合可能な状態同期のほうが長い散文より失真しにくい。

検収に主観だが操作可能な検査を一つ足すことを勧める：ツール軌跡 10 段を抜き、当該タスクに参加していないエンジニアにモデル自述から「何をしたか、何をしていないか」を復唱させる；復唱失敗率が下がってはじめて文風改善が実現したとみなす。

## 安全工学チェックリスト（Sol/Luna 発版週）

1. **分帯 ACL**：どのワークスペースが Astra を許し、どれが Sol/Luna のみか。
2. **model id を記録**：請求と監査は実モデル名で集計し、「GPT-6」一鍋にしない。
3. **拒答と降格の警報**：整列改善はゼロ拒答を意味しない；方針拒答を能力失敗から分ける。[1]
4. **蒸留とプロンプト注入**：Sol/Luna 公告は Opus 5.5「preserved thinking」に相当する統合破壊項を展開しない；履歴コンテキストを書き換える代理層があるならなお回帰テストし、挙動が 5.6 と完全同一だと仮定しない。
5. **Critical cyber 意識**：Astra の Critical 評価が警告する——ピークモデルを書込可能な shell・パッケージインストール可能な環境に繋ぐとき、隔離と承認は安い帯より厳しく。[5]

## 「モデル名だけ換える」の反対にある統合検査

多くのチームは発版日に `model=` 一行だけを変える。GPT-6 世代では少なくともさらに五事を検査する：

1. **effort パラメータが旧封装に飲み込まれていないか**。Sol/Luna の対比は大量に high / xhigh / max 等の帯に立つ；ゲートウェイが medium を書き死していれば、公告の優位図はあなたと無関係。[1]
2. **ツールリストの並びが安定か**。キャッシュブレークポイントと接頭辞再利用は安定接頭辞に依存；動的挿入はヒットを下げる。
3. **システムプロンプトがユーザー次元で連結されていないか**。ユーザーごとに異なる長い方針があると、「デフォルトより高いヒット」は実現しにくい。
4. **出力長ペナルティと切詰方針**。文風が短くなったあと、旧の「強制 2000 token 詳解」テンプレは金を浪費しうる。
5. **評価セットは更新されたか**。5.6 時代の黄金セット流用は可だが、「事実性機微」と「マージ可能性機微」部分集合を単列し、平均点が回帰を隠さないようにする。

この五步を終えてから「GPT-6 へアップグレードした」と宣言してはじめて、財務と品質責任者の双方に正直だ。

## 結び

GPT-6 Sol と Luna の主線は「また世界第一を宣言する」ことではなく、OpenAI が Astra ピークのあと、同世代方法と整列進展を**規模化可能な価位**へ敷き、キャッシュ基盤で長い agent セッションの有効コストをもう一刀削ることだ。[1] Astra はなお最も難しいプロジェクトを守り；Enigma MVUEH 類の第三者記録はピーク帯の研究型能力物語が続いていることを警告する。[6] 符号化 agent 責任者により有用な動作は：分帯ルーティング、キャッシュ接頭辞の修正、自分のマージ率とドルでの検収——Claude 側と対照するときは姉妹篇を読む。[2]
