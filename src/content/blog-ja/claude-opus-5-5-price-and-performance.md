2026 年 9 月 22 日、Anthropic は Claude 5.5 系列の初モデル **Claude Opus 5.5** を公開した。[1] 公式の語りは率直だ：大半の仕事で Claude Fable 5.1 水準に達し、Opus 5 比で典型負荷のコストは約 40% 安く、出力はより速く、自社の行動監査ではこれまで最良のスコアを取った。同日やや遅れて OpenAI が GPT-6 Sol と Luna を出し；両社はほぼ並んで発版し、読者は自然に対照する。姉妹篇は [GPT-6 Sol、Luna と Astra](/ja/blog/gpt-6-sol-luna-and-astra/)。[2]

本稿は Opus 5.5 だけを書き、「coding agent のデフォルトモデルを切替えるべきか」の側に立つ：価格の計算、公式ベンチの意味、安全制限がどの実仕事を塞ぐか、および当サイト既存の Claude Code / agent harness 記事とのつなぎ方。数字は一律公式ページを優先照合；二次稿は背景のみで、未照合価格は捏造しない。

## 公開ウィンドウ：なぜ今回は単独で書く価値があるか

過去一年、モデル発版はますます「能力 + 単価 + 防護」の三点セットに見える。Opus 5.5 の特別さは三事が重なる点だ：

1. **位置付けの引き上げ**：Anthropic は明示する——大半の仕事で Fable 5.1 水準に達し、同時に Claude 5.5 家族の第一弾；Sonnet 5.5 / Haiku 5.5 は続く数週間で追いつく。[1]
2. **単価とタスクコストの双方低下**：百万 token 標価は Opus 5 比で小幅に下がり、キャッシュ読取価格の下げ幅はより大きい；さらに「同じタスクにより少ない token / より少ない歩数」が重なり、公式テストでは典型負荷の総コストが約 40% 減。[1]
3. **安全ナラティブがより硬い**：これは Anthropic が CEO の「フロンティアのリズムを緩め、安全が能力に追いつくように」との呼びかけのあと初の正式発版；外部評価方は Frontier Design と METR を含み、Fable 5.1 同級の生物・ネットワーク安全防護を伴う。[1][3]

日常的に Claude Code を回し、長時間リポジトリを直すチームにとって、これは「また一つのランキング上昇」ではなく、デフォルトモデル・予算上限・失敗フォールバック方針が変わりうる節点だ。当サイトはこれまで [Claude Code の harness 構造](/ja/blog/inside-claude-code-agent-harness/) と [Jev × Claude Code の実装経路](/ja/blog/jev-claude-code-10x-and-25-lines/) を書いた；本稿が補うのは**モデル層**の価格と制限であり、インストールとスキル接続の細部は繰り返さない。[4][5]

TechCrunch もリズムを指摘する：Opus 5（2026-07-24）から約二ヶ月で再び旗艦；同日 OpenAI 発版とほぼ密着し、競争信号は強いが、読者はなお公式パラメータと自社請求を正とし、見出しの「誰が勝ったか」ではない。[3]

## 価格：先に表を見、次に「一件を終わらせる」を見る

公式が与える百万 token あたり価格は次のとおり：[1]

| 項目 | Claude Opus 5.5 | Claude Opus 5 |
| --- | ---: | ---: |
| キャッシュ読取（cache reads） | $0.20 | $0.50 |
| 入力 | $4 | $5 |
| 出力 | $20 | $25 |
| キャッシュ書込（cache writes） | $5 | $6.25 |

別に **Fast mode**（Claude Code と Claude Platform）：入力 $8 / 百万、出力 $40 / 百万。公式は最高約 2.5 倍速と称する。[1]

入力出力だけ見ると下げ幅は約 20%。本当に差を開くのは二点だ：

- **キャッシュ読取が 60% 減**。Agent と coding の仕事では、コンテキスト・ツール結果・リポジトリ断片の繰り返し読みが請求の大半になりがち；Anthropic もキャッシュ読取が大半の agentic / coding コスト主体を成すと明示する。[1]
- **同一タスクに要する token と歩数がより少ない**。公式の書き方は：単価が低い + タスクあたり token が少ない、合わせて典型負荷約 40% 減；出力速度は Opus 5 比で 30% 超向上。[1]

したがって選定時は「百万あたりいくら」だけを比べてはいけない。より工学に近い問いは：一夜の移行、一回りの多リポジトリ監査、一度の Cursor / Claude Code 長セッション——**終わらせるのにいくらかかり、人が張り付いて手戻りするか**。OpenAI も同日 per-task コストを強調；両社の口径は一致し、市場が「ピーク知性」から「単位タスクコスト」へ移ったことを示す。[2][6]

購読面：Anthropic は Pro / Max / Team / 席単位企業プランの五時間用量上限が上がり、自ら時機を選べるレート制限リセットを提供すると述べる。[1] 具体枠はコンソール準拠；本稿は数字を臆造しない。

API モデル識別子は `claude-opus-5-5`。Claude Platform および AWS、Google Cloud、Microsoft Azure で上線済み。[1]

### 再現可能な粗い計算枠（自分の trace を使う）

以下は公式公式ではなく、公告のコスト構造を検査可能な手順に落とし、「聞こえるほど安いのに月末請求が変わらない」を避ける：

1. 既存 Opus 5（または現行デフォルト）ログから直近 20 の**完了済み** agent タスクを抜き、入力 token・出力 token・キャッシュ読取・キャッシュ書込・壁時計時間・人手手戻り有無を記録する。
2. 上表の単価で「単価だけが 5.5、用量は不変」の対照請求を再計算——これが**純標価効果**。
3. さらに出力と非キャッシュ入力が各 20%–40% 減ると仮定（公式の「より少ない token / 歩数」方向由来であり保証ではない）し、**効率効果**の区間を得る。
4. Fast mode を別列にする：「人が待っている」対話経路だけに速度を買い、デフォルト全開にしない。
5. 「防護で Opus 4.8 へフォールバック」したタスクを別会計にする：フォールバック成功も業務完了だが、モデル名と単価はすでに変わっており、総帳に混ぜると 5.5 の費用対効果を誤判する。

第三ステップの楽観仮定でもまだ安くなければ、問題はだいたい harness（無効再試行、コンテキストのチャーン、ツール記述の毎ラウンド書き換え）にあり、モデルが値下げしなかったことではない。これは当サイトが Claude Code harness を論じたときの結論と同方向：モデルは請求の一部にすぎない。[4]

## 公式ベンチ：何を信じ、何を信じないか

Anthropic は対照表を出し、Opus 5.5、Fable 5.1、Opus 5、および彼らが引用する GPT-6 Astra、GPT-5.6 Sol（一部条目）を覆う。抜粋は次のとおり（完全脚注は公式ページ）：[1]

| 評価 | Opus 5.5 | Fable 5.1 | Opus 5 | GPT-6 Astra | GPT-5.6 Sol |
| --- | ---: | ---: | ---: | ---: | ---: |
| Terminal-Bench 4.0（agentic coding） | 66.4% | 55.8% | 52.3% | 57.9% | 37.3% |
| FrontierCode v1.1 Main | 54.4% | 50.3% | 48.0% | 53.3% | 47.5% |
| CursorBench 4.0 | 57.8% | 51.8% | 46.6% | — | 41.7% |
| GDPval-AA v2.1（知識仕事 Elo） | 1846 | 1735 | 1708 | 1542 | 1588 |
| AutomationBench（Zapier） | 40.0% | 31.4% | 26.9% | 41.4% | 28.8% |
| Humanity's Last Exam（ツール含む） | 67.7% | 65.6% | 63.6% | 57.2% | — |
| Terminal-Bench-Science 0.1 | 58.7% | 52.6% | 29.0% | 64.6% | 22.4% |
| OSWorld 2.0（partial） | 81.8% | 80.7% | 74.0% | — | — |

この表を読むときは三つの公式脚注を携える：

1. **effort / harness が一致しない**。例えば Terminal-Bench 4.0 で Opus 5.5 は xhigh、Astra は OpenAI 公表の high；異なる harness と試行回数はノイズをもたらす。公式はさらに Terminal-Bench 上 Opus 5.5 の標準誤差が約 ±2.6 ポイントの規模だと示す。[1]
2. **生産防護が点を落とす**。公式は明記：評価は生産級防護をオン；ネットワーク安全タスクが遮断されたときは Claude Opus 4.8 が接手し、生物とフロンティア LLM 開発類は Opus 5 が接手——これは Opus 5.5 の関連ベンチ見かけ点を**押し下げる**。[1]
3. **AutomationBench はフォールバックなしだとより厳しい**。Zapier 採点で防護介入を失敗とみなしフォールバックモデルがなければ、実業務の「フォールバック後なお完了」体験より点は低くなる；表では Astra が AutomationBench でなお Opus 5.5 より高い（41.4% vs 40.0%）。[1]

Anthropic 自身も認める：能力がこの帯に達すると、**ランキング点数差は実仕事の差ほど信頼できない**；社内利用では Opus 5.5 と Fable 5.1 の体感差は点数が暗示するより狭い。[1] これは読者経験とも一致する：長いリポジトリ移行、曖昧要件の多ファイル改修、人が何度も訂正する必要があるか——一、二ポイントより「換える価値があるか」を決めやすい。

コスト効率面で公式はいくつかの相対結論を強調する（なお公式ページ準拠、勝手に絶対ドルへ換算しない）：[1]

- FrontierCode デフォルト effort 下、GPT-6 Astra 比でタスクあたり約**五分の一コスト**で勝つ；
- Terminal-Bench 4.0 上、約 **40% コスト**で Astra に並ぶ；
- CursorBench 上、GPT-5.6 Sol 比で約 11 ポイント高く、コストは約三分の一。

これらはいずれもベンダー自己報告の対照だ。交叉読みでは OpenAI の Sol/Luna 公告も同時に開く：相手は自分が優位な AutomationBench、DeepSWE、OSWorld 切片で「より安い」を語る。[2] **同一日の二通のニュース稿は、同一の独立再現報告ではない。**

### 反例：「より高得点」がかえって高く、悪くなるとき

公式と二次報道はいずれも一類の現象に触れる：test-time compute / effort を上げても、FrontierCode のよう「改動範囲の規律」を強調する点数が単調に上がるとは限らない——モデルが無関係ファイルを多く直し、採点に罰せられることがある。[1][6] 工学チームへの対応する落とし穴は：

- すべてのタスクをデフォルトで max effort にすると、セッションが長くなり請求が上がり、マージ品質はかえって落ちる；
- 「単発最高点」のデモ設定で生産予算を見積もる；
- 防護介入を無視する：表面上「失敗」だが実際は方針がモデルを切っており、それで 5.5 が「安全関連の仕事ができない」と認定してしまう。

より堅実なやり方は：**タスク種別ごとに effort 帯を固定**（日常 medium、難件で昇格）し、レポートで「能力失敗 / 方針フォールバック / 人手要件変更」の三類を分けることだ。

## 符号化と長タスク：早期テスターは何を言っているか

公式事例では、符号化向け信号は「より長く、より散らばり、手戻りがより少ない」に集中する：

- あるテスターが約 **68 万行** のコード移行を一日未満で完了；同種の仕事を工学チームに任せると数週間かかりうる。[1]
- 別例：約 **20 万行** のコードベース監査と修復で、Opus 5.5 は 3 時間未満、Opus 5 は 20 時間超かつ token 用量約 2.5 倍。[1]
- 内部で HAProxy を C から Rust へ移植：両者ともほぼ原回帰テストを通るが、Opus 5.5 は 9.5 時間、Fable 5.1 の 12 時間より短く、コストは約 51% 低い。[1]
- ウェブ性能：全サイト各ページの読み込み時間を下げる要求で、Opus 5.5 は 40 回中 39 回成功；Opus 5 の改善幅はより小さく、ときにアプリ挙動を変える。[1]
- GitHub、Lovable、Kiro、取引とコンサル顧客などが「より少ない歩数 / より少ない token / 一夜無人監視」類のフィードバックを提供；これらはベンダーが選んだ推薦で、仮説としては適するが、あなたのリポジトリの保証ではない。[1]

coding agent 責任者への着地解釈は：

1. **デフォルト medium effort で足りることが多い**。公式文案は何度もデフォルト設定下の費用対効果を強調；すべてを max にしても必ずしも得ではない。[1]
2. **長セッションの請求構造が変わった**。キャッシュ読取値下げ + より短い軌跡は、「一夜掛け」の限界コストを下げる；だがツールループ・ログ・人手検収ゲートはなお管理が要る。
3. **文風改善が審査コストに効く**。公式は Opus 5 と 5.5 の説明方式を大量に対比：より先に結論、より少ないjargon。PR 記述とセッション記録に頼って監査するチームでは、「モデルの冗長を読む」時間が直接減る。[1]
4. **「最も安全な coding agent」は製品の組合せ拳**。公告はさらに動作前分類器、監査可能なオープンソースサンドボックス、マージ前コード審査、Gray Swan 等評価で Fable 5.1 と並ぶ低いプロンプト注入成功率に触れる。[1] モデル点はその一層にすぎない。

すでに Claude Code を使っているなら、今回の発版を **A/B：同一批の実タスク、固定 harness、完了率・手戻りラウンド・ドルコストを比べる** 機会とみなし、公開ランキングだけを見ない。当サイト harness 文が論じるのは構造；本稿が補うのはモデル交換時の計量口径だ。[4]

### 推奨の一週間検収シナリオ（そのままコピー可）

目標：「デフォルトモデルを `claude-opus-5-5` に切るか」を決めることであり、感想を集めることではない。

1. **タスクプールを選ぶ**：機械移行 / 依存アップグレード 8；多ファイル曖昧要件 6；外部文書読みが要る統合修復 4；意図的な権限越えまたは機微安全プローブ 2（防護観察用で、脱獄追求ではない）。
2. **変数を固定**：同一リポジトリスナップショット、同一システムプロンプトとツール集、同一 effort 起点（推奨 medium）、途中のモデル切替禁止（フォールバックイベントとして記録する場合を除く）。
3. **記録フィールド**：一度でマージ級完了か、人手編集行数、ツール呼び出し回数、キャッシュ読取比率、ドル、安全フォールバック発火有無。
4. **通過線（例）**：ドルが旧デフォルトの 90% 以下で、マージ級完了率が旧モデル以上；または完了率横ばいだが人手編集行数が 30% 以上減。リスク選好に合わせて数字を変える。
5. **失敗帰属**：「できない」「できたが文風が合わない」「方針フォールバック」「評価タスク設計の穴」（例：指示自体に誤りがありモデルが指摘——公式の金融評価にも訂正指示の例がある）を分ける。[1]

## 知識仕事とコミュニケーション：符号化以外の二線

Opus 5.5 は coding モデルだけではない。公式の知識仕事側信号は：

- 「決算が探しにくい」模擬ウェブで四半期報告を書き、自動採点が数字と引用を照合：18 件中 16 件が通過線；Fable 5.1 と Opus 5 は同一設定で通過しなかった。[1]
- GDPval-AA v2.1 で Elo 1846、Fable 5.1 の 1735 と Opus 5 の 1708 より高い；デフォルト effort 下でも max effort の Astra に対しコスト優位ナラティブがあると称する。[1]
- 買収財務モデル + 幹部デモ：Opus 5 と結論は近いが、5.5 はより完全で読みやすく、所要 63 分対 93 分、コスト約 50% 安い。[1]

コミュニケーション側は Opus 5 ユーザー不満が集中する領域だ。公式の並列表例は：5.5 がより早く「追加の下落は課金再構築バグ由来」のような結論句を出し、マネージャー向け要約に合う構造だと示す。[1] agent チームにとってこれは：**同じ一度のツール軌跡でも、後人が審査し引き継ぐコストが下がる**——これは token 請求にほとんど現れない隐性人時だが、「agent に一夜を任せられない」決定にはしばしば現れる。

## 安全と制限：旗艦能力は同級ゲートを伴う

Anthropic は明記する：Opus 5.5 は生物とネットワーク安全能力で Claude Mythos 5.1 に比肩しうるため、Fable 5.1 に近い防護を採用する。[1]

要点整理（細部は System Card とヘルプセンター準拠）：

- **ネットワーク安全**：大半のネットワーク安全類タスクは **透明フォールバック** で Opus 4.8 へ；通常開発ライフサイクルのバグ探し / 修正はなお使える。防御側向け Cyber Verification Program は Opus 5.5 へ拡張され、より緩い受信階層を含む；Claude Security はすでに Mythos 5.1 と組み合わせ可能。[1]
- **生物**：Fable 5.1 と同じ生物防護；阻まれた研究開発は **Life Sciences Verification Program** で申請でき、検証済み学術ラボ・スタートアップ・製薬など向け。[1]
- **蒸留防護**：Fable 5.1 で導入した **preserved thinking** を入れ、API ユーザーが先行コンテキスト書き換えで推論を抽出するのを阻む；2026-08-31 以降に新規作成した API アカウントの関連モデル利用に適用。[1]
- **整列評価**：自動化行動監査は約二千シナリオを覆い、公式は複数のずれ行動指標が最近の Claude より良いと称する；新しい「越境」評価では、境界を迂回しようとする頻度が Opus 5 / Mythos 5.1 比で約 85% 低く、試みは大半が低重大度で自己報告する。[1]
- **正直な限界**：公式はモデルがしばしば自分が評価中だと気づけること、それが実配備行動への外挿を弱めることを認める；説明的監視はなお建設中。同時に強化学習環境フィルタの締め、整列報酬と自動化シナリオ生成の改善を進めている。[1]
- **その他**：ゼロデータ保持を支持（従来 Opus と同じ）；EU AI 法に合わせた透かし措置；thinking モードのオフはもはや支持しない。[1]

工学チームへの実意味：

- agent が脆弱性研究・攻防演習・生物配列設計などに触れるなら、**先にフォールバック発火有無を確認**し、「フォールバック後もタスク成功か、どう会計するか」の経路を設計する。
- 主に製品コード・移行・審査・知識仕事なら、防護はより「境界が安定し、難逆操作を勝手にしにくい」として現れ、自動化無人監視場面に直結する。[1]
- 代理層や多テナント API を保守するなら、preserved thinking が「履歴コンテキスト改変」類統合を壊しうることに注意；公式はヘルプセンター説明と文書を提供する。[1]

TechCrunch の報道は公式と一致：同級防護はコンパイル済みプログラムでの利用発掘や、識別可能な生物兵器関連仕事などを制限し；これが Amodei の pacing 呼びかけ後の初発だと指摘する。[3]


## 「標価だけを見る」の反対にある三類請求の罠

発版週でいちばん多い誤判は、公式表の読み違えではなく、全く異なる三種類のお金を一枚の図に混ぜることだ：

1. **標価下落 vs 用量上昇**。五時間枠の引き上げとレートリセット利用可能は、チームが長タスクをより開きやすくする；単価が下がっても総支出は上がりうる。分母は「成功マージ / クローズしたチケットあたり」にし、日消費ドルだけを見ない。
2. **Fast mode の滲出**。対話経路が速度を要する場合に Fast mode を開くのは合理的；CI のバッチ agent や夜間移行も $8/$40 を走らせると、「旗艦が安くなった」ナラティブを相殺する。設定上 Fast mode は明示選択にし、大域デフォルトにしない。[1]
3. **マルチクラウドと代理の上乗せ**。モデルが AWS / GCP / Azure に上線したあと、クラウド市場と自前代理はしばしば独自の課金と最低消費を持つ；Anthropic 本站表で予算を立て、別経路で発注すると「公告と合わない」偽矛盾が生まれる。[1]

この三類はモデル知性と無関係だが、発版後二週間の財務会で「安くなったはずの 40% は？」になりやすい。分母と経路を検収シナリオに先に書き込むほうが、もう一枚のベンチ表より有用だ。

## GPT-6 家族との対照（本稿独立結論）

姉妹篇が Sol / Luna / Astra を展開する。[2] ここでは Opus 5.5 読者に足りる対照枠だけを与え、二篇が互いに水を注ぎ合わないようにする：

**どう選ぶか（coding agent）：**

1. **すでに Claude Code / Anthropic API 上**：優先して実タスクで Opus 5.5 デフォルト effort を試し；キャッシュヒット・歩数・手戻りをレポートに書く。生物/ネットワーク機微仕事は先に発火テストを一周する。
2. **多モデルルーティング**：ピーク知性は Astra または Fable 帯、日常反復は Sol / Opus 5.5；タスク種別と失敗代償でルートし、ブランド忠誠ではない。
3. **相手ニュース稿の「相対コスト」で直接予算を立てない**：harness、effort、フォールバック費用含否は不透明；自分の trace 請求を正とする。
4. **判断層と分ける**：Jev のような構造化意思決定モデルでルーティング/ゲートするなら、旗艦チャットモデルを換えても判断層をやり直す必要はない；境界は当サイト Jev 文。[5]
