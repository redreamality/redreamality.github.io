代理式编程的外循环

Loop Engineering：设计 Agent 外循环

不再由人反复给编码 Agent 写下一条提示，而是设计一个系统：自动发现工作、运行有限尝试、用独立证据作判断、保存状态，并知道何时停止或升级给人。

系统全貌

工程化外循环，而不只是优化下一条 Prompt

编码 Agent 本身已有内循环：观察、行动、再观察。Loop Engineering 在外层补上任务选择、尝试装配、证据验证、状态保存与结果路由。

设计动作 01

把意图变成可执行契约

没有边界的递归目标会反复打转。外循环需要可观察的成功标准、单次尝试范围、预算，以及通过、重试和升级的明确路线。

设计动作 02

让一次尝试只完成一个有限任务

单次内循环负责调查、修改一个切片、运行检查并记录证据。检查失败不是白费：外循环会把失败转成下一次尝试所需的更好上下文。

设计动作 03

让“完成”成为裁决，而不是感觉

模型往往会宽松地评价自己的工作。Loop Engineering 把执行与裁决分离：测试、策略、日志、diff 或人工审查所产生的证据决定下一条路线。

设计动作 04

把记忆移出对话窗口

长对话会漂移，上下文窗口也会重置。可靠循环把目标、工作队列、测试输出、决策与未解决失败保存在持久 artifact 中，供下一次运行读取。

设计动作 05

看清 Loop Engineering 里的五层循环

这个新兴术语不只指任务重试。完整系统把 Agent 执行、独立验证、任务运营、Harness 改进与承担后果的人类外循环嵌套在一起。
