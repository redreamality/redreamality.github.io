THE OUTER LOOP OF AGENTIC CODING

Loop Engineering

Stop being the person who repeatedly prompts the coding agent. Design a system that finds work, runs bounded attempts, judges independent evidence, persists state, and knows when to stop or escalate.

System overview

Engineer the outer loop, not just the next prompt

A coding agent already has an inner loop: inspect, act, observe. Loop engineering adds an outer system that selects work, frames each attempt, checks evidence, stores what happened, and routes the result.

Design move 01

Turn intent into an executable contract

A recursive goal without boundaries can thrash forever. The outer loop needs observable success, a scoped attempt, a budget, and explicit routes for pass, retry, and escalation.

Design move 02

Let one attempt do one bounded job

The inner run investigates, changes one slice, runs checks, and records evidence. A failed check is not wasted effort: the outer loop turns it into better context for the next attempt.

Design move 03

Make completion a verdict, not a feeling

Models are generous judges of their own work. Loop engineering separates action from judgment: evidence from tests, policies, logs, diffs, or human review determines the next route.

Design move 04

Move memory out of the conversation

Long chats drift and context windows reset. Reliable loops keep the goal, work queue, test output, decisions, and remaining failures in durable artifacts that the next run can read.

Design move 05

See the five loops inside Loop Engineering

Current usage spans more than task retries. The full system nests execution, verification, operations, harness improvement, and a human outer loop that owns consequences.
